# 退出提醒复用 Empty Trash 计划

本文记录 0.4.25 的历史实现；用户后续明确要求调用方不定制弹窗，现行已删除来源上下文、跳过和额外抑制选项，见 [完全相同弹窗计划](exact-trash-dialog-plan.md)。

目标：退出/关闭窗口提醒直接清空废纸篓，复用首页按钮入口，统一危险操作确认、忙碌门禁、Finder 执行、确认令牌、错误展示、空间刷新与提醒状态。退出必须等待清空结果，取消或失败不能悄悄退出；保留明确的“继续退出/直接关闭”和“不再提醒”。不执行真实废纸篓操作，本轮仅编译打包，不提交推送。

现状：按钮走 TrashReminderController.requestEmptyTrash → FinderTrashEmptying.execute → finishTrashEmptying；退出提醒走 NSWorkspace.open(.Trash)，delegate 随即 terminateNow；窗口关闭观察器调用同一旧提醒。

方案：在既有控制器中增加按钮/关闭/退出三种调用上下文与确认结果，公共入口返回可等待的 Task<Bool, Never>，所有清空仍只执行 FinderTrashEmptying。退出 delegate 用 terminateLater/reply 等待成功，失败或取消撤销退出，显式跳过允许退出；窗口关闭不结束进程。提醒忙碌时不启动另一操作。空间测量完成后才释放忙碌门禁。保留三种上下文不同的退出选项，共用同一永久删除警告，只确认一次。

考虑过：①仅将“打开废纸篓”替换为按钮方法，改动少但立即退出会截断任务且重复弹窗；②另建退出清空服务会重复门禁/结果处理；③复用既有控制器并等待结果，覆盖实际生命周期，采用③。

反思：接口复用必须覆盖退出等待与结果后处理，只复用 Finder 命令会留下“调用相同却先退出”的缺口。局部建议：单一确认和执行入口 100/100；全局建议：退出生命周期等待且容量刷新后收口 100/100，均实施。无新增依赖，主体 Swift，无 requirements.txt/conda 变动；根目录 AGENTS.md 与 .trae/rules/project_rules.md 不存在，沿用既有 Tests 存放验证素材并保留前序改动。

定向自检通过，运行时变异验证证明 terminateNow 会触发失败，最终已恢复正确代码。独立复核无重要缺陷；另以逐字复制生产代理的原生 AppKit 探针通过实际 terminateLater/reply。初始探针错误地用主队列 Task 调用 terminate 导致嵌套队列阻塞，改为原生运行循环事件后通过，此为验证夹具修正。正式 0.4.25（139）构建通过 315 项 XCTest，包、镜像与安装检查及原生确认取消均通过。
