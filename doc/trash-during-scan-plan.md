# 扫描期间清空废纸篓

目标：已经显示的确认框必须能执行 Empty Trash；只读扫描不能作为清空的禁用条件，关闭及首页按钮使用同一执行资格。

根因：0.4.29 将提示与执行分开，却保留 canBeginTrashEmptying 的 !isScanRunning 和 allowsEmptying=false 弹窗分支。用户指出这种只允许 Cancel 的确认没有可执行选择。

依据：大文件索引、递归扫描和内容分析均复用 DeletedContentScanExclusion 排除废纸篓；模块进度接收不依赖 trashEmptyingInProgress。清空已有 Trash 无需取消只读扫描。

- [x] 统一门禁，移除扫描限制、disabled alert 分支和无效扫描说明；保留真实写入/恢复/更新/权限等互斥，以及清空去重。
- [x] 覆盖关闭与手动入口、成功与失败；执行器挂起期间继续接收模块进度，不能取消扫描、重复执行或更改清理统计。
- [x] 保留关闭独有“不再提醒”、设置恢复、Cancel 可完全退出及终止后不重复提示。
- [x] 更新文档、逐文件审查，正式构建升版 0.4.30 (144)，318 项测试、签名、App/DMG比对通过；保留运行中的 0.4.29，不提交、不推送，不清空真实 Trash，不中断用户扫描。

反思：此前用保守执行门禁造成了没有有效主操作的确认框，测试也固化了这个错误。局部删除无效能力参数 100/100；全局以真实模型进度与挂起执行器验证并发 96/100，实施。没有新依赖，不引入删除队列或扫描暂停机制。
