# 设置中的项目扫描目录实施计划

目标：设置提供可配置多个项目扫描根目录的入口；列表显示三行高度，更多目录在列表内滚动。三行是可见数量，不改为仅扫描前三个目录。

方案：复用 ProjectScanRootsStore 与现有 project-scan-roots.json。Settings 使用可编辑草稿，原生面板一次添加多个目录、逐行移除，统一保存或撤销；移除仅改变配置，不删除磁盘目录。项目页既有选择入口共用持久化与刷新路径。保留全部默认/用户目录，不写死用户名。

技术：Swift 6、macOS 13、原生 SwiftUI/NSOpenPanel，无新增依赖。沿用当前工作区并保留所有既有未提交修改，不提交或推送。根目录无 AGENTS.md、CONTEXT.md 或 .trae/rules/project_rules.md。

## 复核重点

1. Settings 草稿不保存就不修改实际范围；重复路径去重，空列表明确保存为空，不暗中恢复默认值。
2. 配置读取/保存失败明确显示，保存失败保留旧数据和可重试的草稿。
3. 保存与扫描/清理互斥；保存完成后结果存在就刷新项目模块，使旧范围结果不会直接继续执行。
4. 项目页与 Settings 使用同一文件；原权限准备和执行前从存储重新验证根目录不绕过。
5. 三行视口不能变成仅保存/扫描三个目录；长路径不挤掉移除控件，更多条目可滚动访问。

方案反思：仅在设置放一个多选按钮无法查看和移除已选目录；逐行立即保存/刷新会打断连续编辑。采用现有存储加草稿统一保存，避免复制配置源或引入新扫描策略。

评分：局部三行滚动 98、添加/移除/保存 100；全局共用配置与刷新/安全门禁 100，均实施。无额外扩展建议。

独立审查修正：保存期间底部继续扫描和权限继续也由模型门禁拦截；项目配置失败提示移至无报告也可见的位置。补充回归先失败后通过，复审通过。不是清除旧 session：协调器每次项目扫描仍读取同一个存储，保留原模块继续语义。
