# 编译脚本自动递增版本计划

目标：按用户最新要求，每次运行 build-app.sh 进入正式编译前自动递增 patch 与构建号，然后完成本次编译与 DMG 打包。取代此前“每修改批次手动 bump 一次、重编不再递增”的流程；单独 verify/create-dmg/publish 不递增。

方案：复用 version.py 的严格读取、patch increment、环境校验与原子保存，新增 next-build 命令，一次返回实际写入的版本/构建号。build-app.sh 在签名、资源、SDK等基础检查后、首次 Swift 编译前调用一次并复用返回值。CI 展示版本如提供须等于递增后的版本，CI 构建号如提供须大于旧构建号，并将实际值保存到 Version.json；校验失败不写入。已经进入编译但后续失败则保留已分配版本，下次脚本运行再递增，不回滚。

技术：现有 zsh 与 Python 标准库、Swift 6，无新增依赖；主体为 Swift，不使用 conda 或新增 requirements.txt。沿用当前工作区、保留所有前序未提交修改，不提交或推送。根目录无 AGENTS.md 或 .trae/rules/project_rules.md，验证资料均在 Tests/build-auto-version。

反思：简单先 bump 再 resolve 会在无效 CI 参数时先写入版本，还可能让 CI 构建号比旧版本更小；把校验、递增、原子保存放在同一版本工具入口可保留单一真实来源。不给编译脚本增加跳过递增选项，符合“每次编译”要求；初步检查失败不进入版本分配，已开始编译后不回滚已使用的号码。
