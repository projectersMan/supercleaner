# 首页与关闭窗口使用完全相同的废纸篓确认

本页保留 0.4.26 统一确认的历史计划。0.4.29 起按用户新要求，关闭提醒额外显示“不再提醒”，手动清空不显示；仍共用工厂及执行器。现行行为见 [关闭提醒选择计划](close-trash-reminder-choice-plan.md)。

## 目标

首页 Empty Trash、主窗口红色关闭按钮及直接退出共用完全相同的原生确认：标题“要永久清空废纸篓吗？”（英文 Permanently Empty the Trash?），仅有 Empty Trash / Cancel 两个按钮，没有按来源变化的文案、跳过路径或“不再提醒”选项。Finder 清空实现保持不变。

## 实施计划

1. 先加入隔离源码回归并记录现状失败；补充原生窗口关闭夹具供主任务统一构建运行。
2. 将确认回调收敛为无来源参数的 Bool；同一原生 NSAlert 创建方法只供首页、关闭与退出共同使用。
3. 保留正字节提醒门槛、既有抑制偏好、成功后确认容量、失败与取消保留提醒、退出等待清空和容量刷新、成功后不重复提醒。
4. 更新现有无 Finder 自检，覆盖统一按钮与无抑制选项、取消与关闭/退出成功及失败；新增实际红色关闭按钮的隔离 AppKit 夹具。
5. 检查本批增量与 git diff；主任务统一编译和运行检查，本子任务不构建、不运行原生 UI、不调用 Finder。

## 生命周期语义

继续观察当前主窗口的 `NSWindow.willCloseNotification`，不替换 SwiftUI 的 `NSWindow.delegate`，不重建窗口或扫描模型。窗口关闭已经开始时，Cancel 只取消清空；窗口仍然关闭，应用继续在后台保留当前扫描会话。明确退出时，Cancel 返回 false 仅表示未清空；0.4.28 起退出 delegate 不再用这个结果否决退出。两条路径的对话框内容完全一致。旧版取消退出语义已由 [用户自主退出计划](quit-without-emptying-plan.md) 修正。
