# 大文件自适应目录分组

日期：2026-11-22。

## 用户行为

左侧 All Large Files，右侧 Duplicate Large Files；默认打开全部并按目录展示。Recommended Cleanup 单独置顶，后面是完整路径标题，下一层平铺该组包含的文件，保留完整文件路径、原选择与保护行为。推荐归属取扫描证据而非当前勾选，手动选择不会导致跳组。一个文件只出现一次；已归项目产物的 DMG 继续沿原逻辑排除。

## 算法与取舍

采用基于共同路径结构的目录树划分，不使用大模型、不预设组数或目录深度，也没有目标文件数量。初始的 12 组限制已按用户反馈删除；不以“尽量少的标题”作为单独目标。

1. 按标准化路径去重，先分出有有效推荐证据的文件。目录组只处理其余文件。
2. 主目录下的独立分支保持分开，例如 Documents 与 Library 不会因为文件少而并成 Home。主目录直属文件独立保留；这只是共同路径边界，最终分组层级不固定。
3. 在每个分支自底向上比较三种表示：全部合在当前共同目录、各子树分别表示、共同前缀收益高的子树独立且稀疏兄弟合并保留。
4. 用路径描述长度比较合理性：组标题按相对 Home 的目录组件数加一个标题单位计价，成员按相对于组根的路径组件数计价。重复的共同目录越多，独立成组越有意义；过碎分组增加标题成本，过宽分组重复大量子路径。只数目录层级，不因文件夹名字特别长而改变权重。
5. 子树的独立成本小于其留在父组时的相对路径成本，才在混合方案中独立。比较完整合并、完整拆分及混合方案，成本相同时保留较少的组。无分叉的路径链直接压缩到共同目录。
6. 每个节点只处理一次分组决策，沿有限目录树返回，不依赖反复拆分直到某个组数。组与文件按路径自然排序；先分组后搜索，搜索只过滤成员、隐藏空组，不改原归属。

所有组的文件集合互斥且并集完整。父路径剩余组仅包含未单列为更具体组的文件，避免大分支重复出现。目录标题与箭头用于折叠/展开；目录前的三态勾选框仅批量修改该组当前可见、可读且可选择的文件，不把目录本身加入删除计划。部分选中时点击补齐全选，全选时点击取消；搜索隐藏项及其它组保留选择。折叠不改变选择，推荐组也支持相同操作。清理仍通过原文件候选、确认与安全复验。

这是可解释的路径关联启发式，不宣称可以仅凭路径理解文件业务语义，也不宣称唯一全局最优。50 个浅层目录各 2 项可合为共同父目录，三个有大量共同路径的分支可各自成组；30 个同样合理的分支会保留 30 组，不截断为 12。分组只读已有扫描结果，不增加磁盘遍历。
