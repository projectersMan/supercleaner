# 关闭提醒、不再提醒与扫描并行

目标：关闭窗口可立即看到清理后的提醒，附“不再提醒”；首页手动 Empty Trash 不显示该选项。扫描继续后台运行，实际清空沿用执行门禁。

现场证据：0.4.28 已成功记录 Project 299 MB / 1 项，Agent 在 6 分多钟时仍 Scanning，首页 Empty Trash 也被禁用。旧实现把提示与执行共用 canBeginTrashEmptying，因此提示被推迟；不是清理量漏计。此前繁忙夹具把延迟提示当正确预期，未覆盖用户需要在扫描期间做提醒选择。

实施：

- [x] 先用真实 AppModel/Controller 回归复现扫描期间关闭不提示；原生夹具改用 NSHostingView + 实际 Observer，并检验手动/关闭两种配置。
- [x] 将“可显示关闭提醒”与“可执行清空”分开。扫描期间关闭立即提醒，清空按钮保持禁用并说明扫描结束后可清空；不排队自动执行永久删除，不中断扫描。
- [x] 同一个 NSAlert 工厂只在关闭提醒显示“不再提醒”，共享同一个执行器。勾选只改变自动提醒偏好，不伪造清空成功；退出 Cancel 仍正常退出。
- [x] Settings 提供恢复自动提醒的开关，复用同一个偏好 key；手动 Empty Trash 始终确认。
- [x] 更新相关回归、当前文档和逐文件增量；正式升版 0.4.29 (143)，318 项测试与验签/DMG比对通过。保留正在运行的 0.4.28 扫描，不自动替换；不提交、不推送。

反思：此前把执行门禁当成提示门禁，虽能通过“等空闲再提示”测试，却偏离关窗时的选择需求。局部拆开两种资格 98/100、全局保留单工厂/执行器并使偏好可恢复 94/100，实施。旧版“完全相同两按钮、无 checkbox”的限制已由本轮明确要求取代，只保留手动确认不带 checkbox。

不新增依赖。测试素材存 Tests；Swift 项目无 requirements.txt 或 conda。保留所有既有未提交修改。
