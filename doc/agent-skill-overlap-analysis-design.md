# Skill 与 MCP 能力包含分析

## 用户确定的范围

以GitHub `projectersMan/supercleaner` 的 `75c9c26` 为清单和清理流程基线，加入EmbeddingGemma 2能力包含分析。Skill与MCP是同等对象：Skill对Skill、MCP对MCP，采用相同计算与预选规则。阈值默认85%，在设置中调整。达到阈值且通过基线现有文件保护/清理资格检查的对象默认勾选，最终删除由用户手动确认。

不附加完整文本一致、同平台、非项目范围等门槛；不增加分类、必填说明、额外证据页面。MCP沿用基线的配置文件清理单元，其服务器名称和已有本机用途说明合并为能力线索。不连接服务，不提取命令参数、凭证、环境变量或请求头；名称无法完整描述能力，这是输入信息的限制，不是MCP专用预选限制。

用户追加要求：Skill/MCP软链接从发现阶段排除，不显示、不分析、不预选。扫描器跳过链接，清单入口以[`AgentCatalogPathPolicy`](../Sources/CleanerCore/AgentCatalogPathPolicy.swift)验证本体、manifest与全部父目录均非软链接，断链同样排除；真实目标经独立路径发现时正常保留。过滤不执行删除，不修改Agent配置，不在分析阶段重新访问manifest。

## 平台与进程边界

主应用、Helper和CLI继续使用GitHub基线的macOS13要求；根Package.resolved保持原样，仅Sparkle依赖。GemmaEmbed0.4.1移至AgentInference独立SwiftPM包（macOS14/arm64），以随App签名的Agent专用可执行文件运行。AgentOverlapAI只使用Foundation管道客户端，通过JSON行顺序请求向量；不改变全局信号处理，取消或失败仅结束Agent进程。模型不重复加载到主程序，不使用动态依赖安装。macOS13或Intel仍可使用其他原有功能和Agent清单，但不启用语义推理。

保留Agent界面/功能，以及用户明确要求的首页布局固定、四行导航、标题栏对齐、四模块独立取消/继续扫描。仅必要的依赖、打包、版本及文档随之修改；其他扫描算法、CLI、文件恢复与发布流程保持远端。设置中的Agent阈值和全部重算入口保留。

## 包含率

[`AgentCapabilityExtraction.swift`](../Sources/CleanerCore/AgentCapabilityExtraction.swift)从扫描快照中的Skill功能描述提取段落/列表项，排除代码块、标题和参考目录，保留表格中的描述；MCP采用安全可见的名称或已有说明。文本由实际EmbeddingGemma 2 similarity任务转为归一化向量，不生成式改写原文。保留所有已提取能力描述，不按64个采样；长段落按句及长度拆分而不静默丢弃，单段至多768字符。扫描快照保留原Markdown标题，避免参考链接被错误当成功能。参数集中在 [`agent-overlap-policy.json`](../Sources/CleanerCore/Resources/agent-overlap-policy.json)，必需参数缺失立即报错。

对于A的每个能力片段，在B中查找相似度至少0.95的片段：

- 单项包含率：A中被B覆盖的片段数 ÷ A片段总数。
- 联合包含率：A中被其他同类对象覆盖的片段并集大小 ÷ A片段总数。
- 每对同时计算A被B包含及B被A包含，不用文本长度预先限制方向。
- 0.95是内部片段语义匹配参数，不是第二个预选阈值；用户可调的预选条件始终是累计覆盖描述数/全部描述数达到85%（含85%）。

例如A有10项能力，B覆盖其中6项，C另外覆盖1项：最高单项为60%（B），联合70%，默认85%时A不预选。再有D覆盖不同的2项，联合90%，A可预选。若C的1项已经在B覆盖范围内，就不能重复累加。

包含率是基于可见能力描述的语义估计，不是对运行行为的验证。100%表示本次能力片段全部获得匹配，不保证两个实现的行为完全相同；这不增加额外的文本一致准入条件。

## 统一预选

[`AgentOverlapAnalyzer.preselectedSourceIDs`](../Sources/CleanerCore/AgentOverlapAnalyzer.swift)对Skill与MCP共用一套规划：

1. 用户主目录`.agents`中的Skill/MCP共享源默认保留；主目录`.cache`下通过基线清理资格检查的真实对象不依赖包含率或模型索引即可预选，尊重用户明确保留。软链接已在进入清单前排除。
2. 其他对象从当前扫描对象的缓存关系计算联合包含率，只保留满足阈值且基线允许选择的候选；保留用户明确取消的决定，与当前平台/显示筛选无关。
3. 优先处理依赖多个对象联合覆盖的复合项，再保留提供覆盖的对象，避免互相包含的一组被全部默认勾选。
4. 已保留来源足以达到阈值时优先采用；用户已手动选中或已默认勾选的缓存不能再作为其他默认删除项的覆盖来源。

应用层仅将Skill目录绑定或MCP配置文件候选映射到同一对象选择接口。不存在“MCP只能手动、Skill可以自动”的规则。

## 缓存与显式重算

[`AgentOverlapStore`](../Sources/CleanerCore/AgentOverlapStore.swift)以actor隔离原子读写 `~/Library/Application Support/SuperCleaner/agent-containment-index.plist`。

- 对象以稳定身份（Skill目录或MCP配置路径）索引，能力向量只存一次。
- 每对存两个方向的覆盖位图，包括零覆盖关系；不重复保存成批片段全文。
- 普通扫描不检测内容变化，也不按正文hash使已知关系失效；全缓存命中时不加载模型、不重新嵌入或比较。
- 仅当前清单内同类对象补齐缺失双向关系（含同批新增）。暂时不可访问后恢复的真实对象复用旧向量补齐关系；已知但本次未发现的对象及旧链接保留历史数据，但不参与新配对、排名、累计覆盖或预选。当前清单变化立即刷新展示参与集合，不等待索引加载。
- 改阈值只复用缓存计算选择，不推理。
- 设置中的“重新计算全部包含关系”会重新扫描Agent资源，清空当前分析对象/关系并重建当前数据；本机用途说明和明确保留决定保留。
- 模型或计算策略改变时要求用户显式重算，不静默重算旧对象。
- 旧v1/v2的分析口径与本需求不同，不沿用旧分数；只导入其中已有的本机用途说明，不修改旧文件。

## 界面

当前分析状态在已有列表页面直接展示；缓存策略不兼容时不能仅显示“尚未分析”并将原因藏在tooltip。旧建议与自动勾选被清除，保留已有设置重算入口，无新操作按钮。

保留GitHub基线清单、分组、路径、大小、复选框及“全部/已选中”与平台筛选。右侧明确标注“其他对象对本项的覆盖”，按单项比例排序展示前3名及路径，以区分同名不同目录；排除同一ID。当前对象的名称、描述、标签、路径、目录数量和大小集中在左栏，Top 3名称/路径/比例集中在右栏，两栏顶部对齐；不显示Combined Coverage汇总行，前3名只是展示上限，内部累计覆盖及预选不变。行仍按最高单项排序（分组及分组内），不展开全局配对列表。

保留此前已授权且不改变可见结构的优化：类型切换只挂载当前Skills/MCP页，使用虚拟化List。设置仅增加全部重算入口，继续使用默认85%的可配置阈值。

## 计算核对与边界

- 实际本机843个对象、319747对旧缓存中自配对为0；截图右侧Video SDK和Meeting SDK是不同目录，原文案和相似名称造成歧义。
- 旧策略把参考链接和相似工作流一并当能力，0.85语义匹配参数使截图中的Zoom及Notion条目全部命中。新提取排除参考目录、保留完整正文描述，并将内部匹配参数校准为0.95。
- 使用4个实际Skill的扫描快照及真实EmbeddingGemma 2缓存向量，由现行分析器重新计算：Video SDK被Meeting SDK覆盖2/8（25%），反向2/7（约28.5%）；Notion实现规划被会议准备覆盖6/31（约19.3%），反向6/35（约17.1%）。四项均未达到85%，重复分析新增0项/计算0对。
- 普通扫描不改写不兼容的真实索引；兼容校验通过前不装入应用建议，升级后沿用设置中的“重新计算全部包含关系”。本次用户明确要求修复缺失排名/预选，已使用相同扫描与分析流程进行一次本机全量重建，先隔离校验再原子替换，不改变后续普通扫描策略。
- 分母是扫描描述中提取出的全部能力片段，而非模型证明的运行时功能全集；模型负责语义匹配，不能证明所有实现行为完全一致。未读取的外部引用文档不被算作已分析功能。

上述为实际数据分析，不是测试套件；没有执行删除。

目录边界：`~/.agents`是共享存放位置，不能保证Claude/Trae自动发现，也不是通用MCP注册表；MCP仍按各Agent自己的配置加载。本机部分入口为软链接，不能为去重删除入口或修改目标。`~/.cache`判断使用当前用户主目录下的真实路径边界，不按目录名包含cache或界面分组文字猜测；其他路径维持原有重叠规则。
