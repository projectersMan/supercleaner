# 渐进式扫描结果设计

## 目标

完整扫描仍由概览统一发起，但任一模块完成后，用户无需等待其他模块，即可从扫描进度行进入对应页面查看该模块的新结果。

## 交互规则

- `通用清理`完成或部分受限时进入`清理中心`。
- `应用`完成或部分受限时进入`应用卸载`。
- `大文件`完成或部分受限时进入`大文件`。
- `Agent 环境`完成或部分受限时进入`Agent 环境`。
- 等待、扫描中、失败或取消的模块不可进入，也不显示误导性的跳转箭头。
- 可进入的进度行使用整行按钮语义、悬停反馈和右侧箭头。
- `查看原因`是独立按钮，只展开限制详情，不触发页面跳转。

## 数据流

`SystemScanCoordinator`在模块完成时发布带类型的模块结果，而不只发布状态。`AppModel`在主线程接收结果并只替换对应模块的数据，同时保留其他模块上一次完整扫描的结果。

扫描过程维护两个层次：

1. 当前扫描代次的模块状态和已完成模块结果，用于即时查看。
2. 上一次完整`SystemScanReport`，用于尚未完成模块的稳定回退。

当所有模块结束后，协调器仍生成一次完整报告；最终安装结果必须与逐模块发布结果一致。取消扫描时保留已经发布的新模块结果以及未被替换的旧结果，不创建一个伪造的完整报告。

## 状态与安全边界

- 只有`.completed`和`.limited`允许进入结果页。
- 模块结果必须与当前扫描的`generationID`一致，迟到的旧任务结果不得覆盖新扫描。
- 页面是否有可查看结果由模块结果是否已安装决定，不能只依据状态文案。
- 渐进式发布只更新内存中的只读扫描结果，不执行清理、隔离或卸载。

## 测试

- 导航策略覆盖四个模块的目标页面及六种状态。
- 模块结果替换测试验证只更新目标模块，不破坏其他模块旧结果。
- 代次测试验证迟到事件不会覆盖当前扫描。
- 完整扫描契约验证最终报告和最后一次渐进式状态一致。
- UI 操作检查验证已完成行可进入、扫描中行不可进入、限制详情不会误跳转。
