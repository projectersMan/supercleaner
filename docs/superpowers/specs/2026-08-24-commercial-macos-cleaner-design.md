# 商业 macOS 清理产品设计

日期：2026-08-24  
状态：待评审  
目标：设计一个可闭源商业化、独立实现、以安全和可解释性为核心的原生 macOS 清理产品。

## 1. 摘要

本产品不是 Mole 的 GUI 封装，也不依赖、捆绑或调用 Mole。产品使用全新品牌、Bundle ID、界面、文案、代码结构和规则格式，从 Apple 文档、应用元数据、厂商资料及实机验证中独立建立清理能力。

首个商业版本是一款完整的 macOS 清理产品，面向普通用户、专业用户和开发者，覆盖系统缓存、应用缓存、安装包、卸载残留、大文件分析和开发环境清理。在完整基础能力之上，产品增加 Agent 工程清理亮点，理解 Codex、Claude Code、Cursor 等 Agent 工具产生的会话、沙箱、Skills、Plugins、MCP Server、Git worktree、模型与包管理器缓存。

产品采用 SwiftUI 原生界面、Swift 6 清理引擎和最小权限 Helper。核心执行模型是 `Scan → Plan → Review → Apply → Verify → Audit`：扫描与删除完全分离；所有破坏性操作必须基于可审查的计划；执行前重新验证目标身份；默认提供可恢复删除；高权限操作只能通过类型化白名单协议完成。

## 2. 产品原则

### 2.1 安全优先于清理率

漏掉一项垃圾只影响释放空间，误删一项用户数据可能造成不可逆损失。因此无法证明安全的目标默认跳过，证据不充分的目标默认不选，系统关键目录和用户内容永不自动选择。

### 2.2 解释优先于黑盒评分

每个清理候选项必须回答：

- 它属于哪个应用或系统组件；
- 为什么被判定为可清理；
- 删除后会有什么影响；
- 是否能够重新生成或恢复；
- 哪条规则和哪份证据作出了判断。

### 2.3 事实可以相同，实现必须独立

公共路径、Bundle ID、文件用途和可再生性属于可独立验证的功能事实。产品可以得出与其他清理工具相同的事实，但不得复制第三方源码、规则文件、规则集合的特有编排、注释、测试、文案或内部结构。

### 2.4 最小权限

普通扫描和用户目录操作由用户进程完成。只有确实需要系统权限的有限操作进入 Helper。Helper 不接受 shell 字符串、脚本、相对路径、通配符或任意命令。

### 2.5 本地优先

扫描结果、完整文件路径和操作历史默认只保存在本机。诊断和产品分析采用显式选择加入；任何上传数据在发送前去除用户名、完整路径和文件内容。

### 2.6 为什么这个方案可以做得更好

产品优势不建立在“发现更多路径”或制造更高的清理数字上，而建立在用户是否理解、是否可控、是否能恢复，以及引擎能否证明操作安全。

| 常见的简单实现 | 本产品的改进 |
|---|---|
| GUI 直接调用命令或解析终端文本 | 原生类型化领域模型，不存在终端输出解析和模拟按键 |
| 静态路径匹配后直接删除 | 归属、用途、活跃性、共享性、边界和恢复性组成完整证据链 |
| 扫描结束后一次性展示巨大数字 | 边扫描边展示，区分“安全释放”“需要审查”“已保护” |
| 用单一健康分数制造焦虑 | 展示可验证事实、实际影响和用户可以采取的动作 |
| 把所有权限一次性索取 | 先提供无权限价值，仅在相关功能处解释并请求必要权限 |
| 删除前只弹出笼统确认框 | 在计划审查页逐项展示原因、风险、恢复方式和权限变化 |
| 成功只表示命令退出码为零 | 执行后重新检查文件系统状态并逐项报告成功、跳过或失败 |
| 删除失败时升级权限或改用永久删除 | 保持最小权限并安全失败，绝不自动降低恢复能力 |
| 规则更新只追求覆盖率 | 规则具备来源、系统版本、测试证据、签名、撤销和回滚能力 |
| 清理之后只显示释放空间 | 提供操作收据、恢复入口、重新生成成本和异常说明 |
| 把 Agent 隐藏目录当作普通开发缓存 | 理解任务、项目、MCP、Skill、worktree 与可重建运行时之间的语义关系 |

这使产品形成三个可感知的差异：清理前看得懂，清理时可控制，清理后能追溯和恢复。

### 2.7 Agent 工程清理亮点

简单的路径清理逻辑只能看到文件夹，本产品还理解 Agent 工程资产之间的关系：一次任务属于哪个 Agent、关联哪个仓库和 worktree、调用了哪些 MCP Server、加载了哪些 Skills、产生了哪些可重建工具缓存，以及哪些内容包含用户知识、凭据或尚未提交的代码。

产品不把 `~/.codex`、`~/.claude` 或项目中的隐藏目录整体视为“缓存”。它先构建语义化资产图，再区分：

- **可重建运行资产**：下载缓存、构建产物、临时沙箱、过期索引和已退出任务的中间文件；
- **需要审查的历史资产**：旧会话、工具输出、截图、补丁和已完成任务快照；
- **必须保护的知识资产**：自定义 Skills、Agent 指令、Prompt、MCP 配置、项目记忆和用户创建的模板；
- **绝不读取或展示的秘密资产**：Token、API Key、OAuth 凭据、Keychain 内容、`.env` 和 MCP Server 密钥。

Agent 工程清理是完整产品中的差异化亮点，而不是唯一定位。它的卖点不是“敢删 Agent 目录”，而是“理解 Agent 工作区，准确区分可重建运行成本与不可替代工程知识”。系统清理、应用清理、卸载和磁盘分析仍构成用户进入产品的基本价值闭环。

## 3. 目标用户与首发范围

### 3.1 首批用户

- 希望安全释放系统、应用和磁盘空间的普通 Mac 用户；
- 使用 Adobe、Figma、视频或音频工具、容易产生大型缓存的专业用户；
- 经常使用 Xcode、Docker、Node.js、Python、Android Studio、JetBrains IDE 的开发者；
- 同时使用多个 Coding Agent、积累大量会话、沙箱和插件版本的 Agent 工程师；
- 开发或维护 MCP Server、Skills、Agent Plugins 和自动化工作流的 AI 原生开发者；
- 频繁创建 Git worktree、并行分支和临时环境的多 Agent 团队成员。

### 3.2 V1 功能

1. 系统与通用应用缓存扫描；
2. 开发环境缓存和可重建产物扫描；
3. 安装包与下载残留扫描；
4. 应用卸载及关联残留审查；
5. 大文件和目录占用分析；
6. 清理计划逐项审查；
7. 废纸篓优先的安全执行；
8. 操作历史、结果验证和恢复指引；
9. 权限状态诊断；
10. 签名规则包的独立更新；
11. Agent 工程资产盘点与可视化；
12. 已完成 Agent 任务的沙箱、日志、截图和临时产物清理；
13. Skills、Plugins 与 MCP Server 的版本和运行缓存治理；
14. Git worktree、Agent 临时分支和项目级工作区安全审查；
15. Agent 相关模型、索引和包管理器缓存的可重建成本分析。

### 3.3 V1 不包含

- 注册表式“系统优化”或未经证明的性能加速；
- 自动结束应用、重启系统服务或修改网络配置；
- 重复照片识别、云盘内容管理和隐私文件粉碎；
- 杀毒、Endpoint Security 系统扩展或后台行为拦截；
- Mac App Store 分发；
- 无人值守的自动永久删除；
- 菜单栏硬件监控与常驻性能面板；
- 自动修改 Agent、Skills、MCP 或 IDE 配置；
- 自动删除会话历史、项目记忆、Prompt、未提交代码或未推送提交；
- 代替 Agent 工具自身执行升级、降级或插件迁移。

这些能力不会进入首版，是为了保持权限模型、测试范围和产品承诺可控。

## 4. 系统架构

### 4.0 界面概念图

概念图验证以下信息架构：通用智能清理保持主入口；Agent 工作区作为高辨识度专题模块嵌入基础清理流程；“可直接清理”“需要确认”“已保护”三种状态同时使用控件、文字、图标和颜色表达；右侧检查器解释影响、可恢复性和包含内容；底部操作栏在执行前汇总真实选择范围。

### 4.1 SwiftUI App

负责展示、用户选择、权限引导和进度反馈，不直接执行文件删除。界面只消费领域模型，不解析终端输出或拼接命令。

主要页面：

- 首页：磁盘概览、最近一次扫描、可安全释放空间；
- Agent 工作区：按 Agent、项目、任务和工具链展示资产关系；
- 分类页：系统、应用、开发工具、安装包、大文件；
- 审查页：按风险和来源展示目标，支持逐项展开；
- 卸载页：应用本体、关联文件、共享数据和运行状态；
- 历史页：每次计划、实际执行结果和恢复指引；
- 权限页：解释缺失权限造成的具体能力差异。

### 4.2 人机交互设计

```text
首次启动
   │
   ▼
当前权限快速扫描 ──权限不足──► 解释能力差异 ──用户选择──► 授权或继续受限扫描
   │
   ▼
安全释放 / 建议审查 / 主动保护
   │
   ▼
逐项审查 ──高风险或不可恢复──► 增强确认
   │
   ▼
计划执行 ──身份或状态变化──► 安全跳过并解释
   │
   ▼
结果收据 ──恢复期内──► 撤销本次清理
```

#### 4.2.1 首次启动

首次启动不立刻弹出 Full Disk Access 或管理员权限请求。产品先用当前权限完成快速扫描，让用户看到实际价值，再在受影响的分类中说明：缺少什么权限、会漏掉哪些内容、授予后会发生什么、如何撤销。

首次体验控制在三个步骤：

1. 说明产品只在本机分析，未经确认不会修改文件；
2. 立即开始可取消的快速扫描；
3. 展示首批结果和被保护内容，而不是要求用户先完成复杂配置。

#### 4.2.2 首页信息层级

首页不使用“Mac 很危险”“健康度过低”等焦虑式表达。首屏提供三个有明确含义的数字：

- **可安全释放**：证据完整、默认可选的可恢复内容；
- **建议审查**：可能需要重新下载、重新索引或重新构建的内容；
- **主动保护**：引擎发现但因用户数据、活跃状态或证据不足而拒绝处理的内容。

用户可以从汇总下钻到分类、应用和具体路径。界面默认显示人类可理解的名称和影响，完整路径、规则 ID 和文件身份放在“技术详情”中渐进披露。

#### 4.2.3 扫描体验

- 扫描开始后 2 秒内展示历史结果和当前进度，不以空白加载页阻塞用户；
- 首批分类结果可用后立即展示，无需等待完整磁盘扫描结束；
- 显示当前扫描区域、已检查项目数和剩余估算，不伪造精确进度；
- 用户可以暂停或取消，取消不会产生任何文件修改；
- 外接卷默认不扫描，只有用户明确选择后才进入对应卷；
- 应用退出或窗口关闭不会把尚未确认的计划自动变成后台清理任务。

#### 4.2.4 审查体验

审查页采用“分类 → 应用 → 候选项”三级结构。每项同时展示：

- 可释放空间；
- 风险等级；
- 清理原因；
- 对下次启动或构建的影响；
- 恢复方式；
- 是否需要额外权限。

安全项可以批量选择，审查项默认不选，保护项不可选择。改变选择后总空间实时更新，但不使用倒计时、闪烁或预选高风险项目推动用户清理。

对于“清理后需要重新下载 8 GB”“下次 Xcode 构建可能增加 12 分钟”等可估算成本，优先展示成本而不是只展示收益。

#### 4.2.5 确认与执行

普通可恢复清理使用一次明确确认；包含应用卸载、系统级变更或永久删除时按风险逐级增加摩擦：

- 应用卸载要求再次展示应用名称、运行状态和保留的数据；
- 系统级操作在授权前展示 Helper 将执行的具体操作类型；
- 永久删除要求单独选择，不能与普通清理共享一个总开关；
- 永久删除确认页明确说明不可恢复，并要求用户再次确认目标范围。

执行过程中逐项展示状态，允许停止尚未开始的项目。停止操作不会强行中断正在进行的原子文件移动，以免制造半完成状态。

#### 4.2.6 完成与恢复

完成页不是庆祝动画，而是一份可操作收据：

- 实际释放空间与计划估算差异；
- 已移动到废纸篓或隔离区的项目；
- 因身份变化、文件占用或权限不足而跳过的项目；
- 可能发生的重新下载、重新索引或重新构建；
- 在恢复期限内可执行的“撤销本次清理”。

历史页允许按一次计划恢复，不要求用户理解内部目录。恢复前同样检查目标位置是否被新文件占用；冲突时提供安全的新位置，不覆盖现有内容。

#### 4.2.7 错误与权限沟通

错误文案采用“发生了什么 → 为了保护什么而停止 → 用户可以怎么做”的结构。例如：

> Docker 缓存仍在被进程使用。为了避免损坏正在运行的容器，本次保留了 4.2 GB。退出 Docker 后可以重新扫描。

权限不足不是红色故障，而是能力降级。产品不得反复弹出系统设置或把拒绝授权描述为用户操作错误。

#### 4.2.8 可访问性和本地化

- 所有核心流程支持 VoiceOver、键盘导航和完整焦点顺序；
- 风险不能只用红、黄、绿表达，必须同时使用文字和图形；
- 支持 Reduce Motion、Increase Contrast 和动态文字适配；
- 进度变化使用节制的可访问性通知，避免连续朗读；
- 路径、大小、日期和快捷键符合系统区域设置；
- 首发界面和安全文案同时提供简体中文与英文，并由人工审校破坏性操作文案。

#### 4.2.9 Agent 工作区体验

Agent 工作区不是路径列表，而是一张面向任务的资产地图：

```text
项目 / 仓库
  ├─ Agent 与会话
  │    ├─ 活跃任务（保护）
  │    ├─ 已完成任务（审查）
  │    └─ 临时输出、截图、日志（可重建）
  ├─ Git worktree
  │    ├─ 干净且已合并（审查）
  │    └─ 未提交、未推送或锁定（保护）
  ├─ MCP Server
  │    ├─ 配置与凭据（保护）
  │    └─ 旧运行版本与包缓存（审查）
  └─ Skills / Plugins
       ├─ 用户自定义内容（保护）
       └─ 可重新下载的旧版本（审查）
```

每张资产卡展示：来源工具、所属项目、最后活动时间、磁盘占用、活跃状态、是否可重新生成、重新生成成本以及保护原因。用户可以按“已结束任务”“90 天未使用的 Agent 资产”“可重建 MCP 运行时”“已合并且干净的 worktree”等语义筛选，而不是手工理解隐藏路径。

清理 Agent 资产前，确认页额外回答：

- 是否影响恢复旧会话；
- 是否需要重新下载模型或依赖；
- 是否会让某个 MCP Server 下次启动变慢；
- 是否存在未提交、未推送或未归档的代码；
- 是否包含用户自定义 Skill、Prompt 或项目记忆。

产品可以提示重复安装和失效引用，但 V1 不自动修改 Agent 或 MCP 配置。配置修复属于后续独立能力，必须与清理计划分开确认。

### 4.3 User Engine

Swift Package 形式的独立领域层，负责：

- 枚举文件系统和应用元数据；
- 运行规则、生成证据并计算风险；
- 建立不可变清理计划；
- 在执行前重新验证路径和文件身份；
- 执行用户权限范围内的移动或删除；
- 记录结构化审计事件；
- 输出可单元测试的纯领域模型。

扫描和分类使用 Swift structured concurrency，但并发受 I/O 预算控制。扫描器不能跟随未验证的符号链接，也不能跨入未选择的外部卷。

### 4.4 Privileged Helper

最低支持 macOS 13，使用 Apple Service Management 机制安装和管理。Helper 通过 XPC 接收类型化请求，只支持预先定义的操作，例如：

- 查询受限目标的文件身份和大小；
- 将已批准的系统级缓存目标移动到隔离暂存区；
- 删除由产品创建且身份匹配的暂存目录；
- 卸载已验证属于目标应用的 LaunchDaemon 或 Helper。

Helper 必须：

- 验证调用方代码签名和 designated requirement；
- 拒绝包含 `..`、控制字符、相对路径或符号链接逃逸的目标；
- 对字面路径和解析后的物理路径分别校验；
- 对设备号、inode、文件类型、所有者和修改时间进行二次绑定；
- 使用独立审计日志记录请求、决定和结果；
- 拒绝 App 未在有效计划中授权的操作。

### 4.5 Rule Store

规则包与引擎分离，但使用内部版本化模型。发布包由产品方签名，引擎只加载签名有效、schema 兼容、适用系统版本匹配的规则包。

规则数据存储以下字段：

| 字段 | 含义 |
|---|---|
| `ruleID` | 永久稳定标识 |
| `category` | 系统、应用、开发、安装包或保护规则 |
| `matcher` | 类型化匹配器，不包含可执行脚本 |
| `ownershipEvidence` | Bundle ID、receipt、签名或父目录归属 |
| `regenerationEvidence` | 可再生性的依据 |
| `risk` | safe、review、blocked |
| `defaultSelection` | 默认是否选中 |
| `macOSRange` | 适用系统版本 |
| `sourceKind` | Apple、厂商、实机观察或内部研究 |
| `sourceReference` | 可审计的来源编号 |
| `validatedAt` | 最近验证日期 |
| `testFixture` | 对应测试夹具标识 |

规则不允许携带 shell、JavaScript、动态库或任意可执行载荷。

## 5. 清理规则模型

### 5.1 通用发现

引擎从系统事实出发动态发现候选项：

- 标准 Library 目录语义；
- 应用 Bundle ID 与代码签名；
- `Info.plist`、LaunchServices 和安装 receipt；
- Homebrew Cask metadata；
- 文件类型、扩展属性、所有者和最近活动时间；
- 运行进程打开文件和应用运行状态；
- APFS 卷边界、克隆文件与硬链接关系。

通用发现产生“候选项”，不能直接产生“可删除”结论。

### 5.2 证据分类

每个候选项经过以下证据链：

1. 归属证据：能否确定属于具体应用或系统组件；
2. 用途证据：是缓存、日志、安装包、可构建产物还是用户数据；
3. 可再生证据：应用或工具能否可靠重建；
4. 活跃性证据：是否被进程使用、近期写入或属于活跃数据库族；
5. 共享性证据：是否被多个应用、版本或账户使用；
6. 边界证据：物理路径是否仍处于允许区域；
7. 恢复证据：能否进入废纸篓或产品隔离区。

任一关键证据未知时，风险只能是 `review` 或 `blocked`，不能是 `safe`。

### 5.3 默认风险策略

- `safe`：证据完整、内容可再生、目标不活跃、归属单一；默认可选；
- `review`：可清理但会产生重新下载、重新索引或重新构建成本；默认不选；
- `blocked`：用户数据、共享状态、活跃文件、系统关键路径或证据冲突；界面只解释，不允许执行。

### 5.4 专项规则的独立生产

厂商专项规则通过以下流程产生：

1. 在干净虚拟机或专用测试机记录安装前快照；
2. 安装并运行目标应用，执行可重复场景；
3. 记录运行后和卸载后差异；
4. 对每个路径判断用途、归属、可再生性和共享性；
5. 使用厂商公开文档或行为测试交叉验证；
6. 建立正向、反向、符号链接和竞态测试；
7. 经人工审核后进入签名规则包。

该流程保留来源记录，以证明规则由产品方独立获得。

### 5.5 Agent 工程清理域

#### 5.5.1 Agent 运行资产

扫描器通过 Agent 公开配置、进程信息、任务锁、文件活动和项目关联发现运行资产。候选项包括：

- 已结束任务留下的临时沙箱和快照；
- 可重新生成的本地索引、搜索缓存和工具描述缓存；
- 工具调用日志、调试日志、崩溃报告和临时下载；
- 任务产生的临时截图、浏览器捕获和中间媒体；
- 已被正式产物替代的临时 patch、diff 和构建结果；
- 已不存在项目或已卸载 Agent 的孤立运行缓存。

会话正文、用户消息、项目记忆和 Agent 生成但尚未归档的交付物不属于安全缓存。它们只能作为 `review` 展示，且默认不选。

#### 5.5.2 Skills 与 Plugins

引擎将 Skills 和 Plugins 分为源内容、安装版本和运行缓存：

- 用户编写或修改的 `SKILL.md`、脚本、模板和资源属于知识资产，始终保护；
- 工作区级 Skill 优先视为项目源码，遵循 Git 状态保护；
- 可从可信来源重新下载且未被引用的旧版本可以进入审查；
- 解压缓存、下载缓存、编译缓存和失效索引可以按证据进入安全清理；
- 无法证明来源、完整性或当前引用关系的版本默认保护。

引擎不得仅因为目录名称为 `skills`、`plugins` 或 `extensions` 就判定可清理。

#### 5.5.3 MCP Server

MCP Server 可能通过本地二进制、源码目录、`npx`、`uvx`、Python、Node.js、容器或远程 HTTP 运行。产品分别处理：

- **配置**：Server 名称、命令、参数、环境引用和授权信息；只读盘点，默认保护；
- **凭据**：Token、Key、OAuth 状态和 Keychain 引用；不读取值、不写日志、绝不清理；
- **运行时**：可重新下载的包、虚拟环境、旧二进制和容器层；根据当前引用和版本进入审查；
- **缓存**：工具列表、schema、图标、日志、临时响应和下载缓存；失效后可安全清理；
- **源码**：用户克隆或开发中的 MCP Server 仓库；按项目源码处理，默认保护。

MCP 工具可能访问外部系统并执行有副作用的操作。清理器只管理本地资产，不调用 MCP 工具来“验证”服务，也不使用配置中的凭据连接远程系统。

#### 5.5.4 Git worktree 与 Agent 临时分支

产品通过 Git 自身的结构化信息识别 worktree，不根据目录名称猜测。任何 worktree 出现以下情况都必须保护：

- 工作区有已修改、已暂存或未跟踪文件；
- 存在未推送提交或无法确认远端状态；
- 分支未合并，或合并状态无法确认；
- worktree 被锁定、正在执行 rebase、merge、cherry-pick 或 bisect；
- 目录被 Agent、编辑器、终端或构建进程使用；
- 主仓库、Git 元数据或关联关系异常。

只有同时满足“无改动、无未跟踪文件、提交可恢复、未被使用、关联仓库健康”的 worktree 才能进入 `review`。V1 不默认选择 worktree，也不直接以文件系统递归删除替代 Git 管理操作。

#### 5.5.5 模型、索引与工具链缓存

Agent 工程常见的大型可重建资产包括本地模型、Embedding、代码索引、npm/pnpm/bun 包缓存、Python/uv/pip 环境缓存、容器层和编译产物。产品为每项同时展示：

- 当前占用与 APFS 实际占用；
- 关联的 Agent、MCP Server 或项目；
- 最近使用时间和活跃进程；
- 重新下载大小、预计耗时和是否需要网络；
- 当前版本是否仍被配置引用；
- 清理后首次任务的性能影响。

离线可用性优先于释放空间。无法确认网络可用或远端资源仍存在时，模型和运行时只能进入 `review`，不能标记为 `safe`。

#### 5.5.6 Agent 资产保护清单

以下类型默认 `blocked`，除非用户在专门的数据管理流程中主动处理：

- Agent 指令文件，如项目和用户级指导文档；
- 自定义 Skills、Prompts、Templates、Hooks 和自动化脚本；
- MCP 配置、授权状态、环境变量文件和凭据；
- 会话正文、项目记忆、人工标注和长期知识库；
- 未提交代码、未跟踪文件、未推送提交和 Git stash；
- Agent 生成但尚未被用户确认归档的文档、代码、图片和数据；
- 活跃任务、运行中 MCP Server 和被占用的沙箱；
- 无法判断归属、来源或重新生成方式的任何资产。

#### 5.5.7 Agent 存储根与 Provider Adapter

不同 Agent 会改变目录和 schema，因此引擎不把某个版本的隐藏路径写死在删除逻辑里。每个受支持工具通过版本化 Provider Adapter 提供发现能力，Adapter 只产生候选资产，不拥有删除权限。

Adapter 需要识别以下存储根类型：

| 存储根类型 | 代表内容 | 默认策略 |
|---|---|---|
| 用户级 Agent 根 | 配置、会话、Skills、插件、日志和索引 | 根目录永久保护，子项分类 |
| 工作区级 Agent 根 | 项目指令、规则、Skills、任务状态 | 视为项目源码，默认保护 |
| macOS Application Support | Agent GUI 数据、下载组件和状态 | 按 Bundle ID 与数据用途分类 |
| macOS Caches / Logs | 可重建缓存、诊断日志和崩溃报告 | 非活跃且证据充分时可清理 |
| 临时目录与沙箱根 | 任务快照、工具输出和中间文件 | 绑定任务终态与活动锁 |
| 包管理器存储 | npm、pnpm、bun、uv、pip 等下载与构建缓存 | 按引用、版本和重建成本审查 |
| 模型与索引存储 | 模型权重、Embedding、代码索引 | 默认审查，保护离线可用性 |
| Git 元数据与 worktree | 分支、引用、锁和并行工作区 | 只通过 Git 状态判断，根永久保护 |

Adapter 的路径来源依次为：工具公开配置或环境变量、官方文档、已签名应用元数据、合法实机观察、最后才是带版本范围的已验证规则。实际执行层只接收标准 Candidate，不接收 Provider 自定义脚本。

任何 Agent 根目录本身都不能成为执行目标。即使 Provider 被卸载，引擎也只能处理已证明可重建的子项，不能把整个遗留目录视为垃圾。

## 6. 核心数据模型与执行协议

### 6.1 Candidate

候选项包含逻辑路径、物理路径、文件身份、归属、大小估算、风险、证据列表和规则版本。大小只是展示信息，不能作为身份依据。

### 6.2 CleanupPlan

计划是不可变对象，至少包含：

- 随机 `planID`；
- 创建时间和失效时间；
- 引擎版本、规则版本和 macOS 版本；
- 用户明确选择的 Candidate 快照；
- 每个目标的文件身份与预期操作；
- 所需权限及不可恢复操作提示；
- 计划内容的本地完整性摘要。

规则更新、系统版本变化或计划过期后必须重新扫描，不能直接执行旧计划。

### 6.3 执行状态机

```text
draft → reviewed → authorized → executing → verifying → completed
                                      ├──────────────→ partial
                                      └──────────────→ failed

draft/reviewed/authorized → expired
```

执行器逐项提交结果，不以“命令成功”代替“目标已达到预期状态”。中断后可以读取日志恢复到可解释状态，但不会自动重放破坏性操作。

### 6.4 执行前重新验证

每个目标执行前必须重新验证：

- 路径仍存在且类型相同；
- 物理解析路径仍位于允许边界；
- 设备号和 inode 未变化；
- 所有者和关键时间戳符合计划；
- 没有新进程打开或写入目标；
- 目标应用状态没有发生危险变化；
- 当前规则版本未撤销该操作。

验证失败时跳过单项并产生明确原因，不扩大操作范围。

## 7. 删除与恢复策略

### 7.1 默认策略

- 用户文件和应用卸载默认移动到废纸篓；
- 可重建的大型缓存优先移动到产品隔离区，验证期后再清除；
- 永久删除仅用于体积过大、废纸篓不可用且用户明确二次确认的目标；
- 跨卷移动失败时不自动降级为永久删除。

### 7.2 隔离区

隔离区由产品创建和管理，按计划隔离，保存原始路径、身份、移动时间和恢复期限。Helper 只能清理自身创建、身份匹配且超过保留期的隔离项。

### 7.3 卸载

卸载流程分别展示：

- 应用包；
- 明确归属的缓存和日志；
- 偏好设置和保存状态；
- 登录项、LaunchAgent、LaunchDaemon 和 Helper；
- 可能包含用户内容或被共享的数据。

共享或高价值数据永不默认选择。应用运行时，卸载默认阻止，而不是自动强制结束进程。

## 8. 权限与隐私

### 8.1 权限策略

产品官网通过 Developer ID 分发并完成 notarization。V1 不启用 App Sandbox，因为全盘分析和跨应用目录访问与沙盒能力不匹配；仍通过进程拆分和 Helper 白名单实现应用内最小权限。

Full Disk Access 只能由用户在系统设置中授予。产品先展示缺失权限影响的具体分类，再提供跳转指引；用户拒绝后继续提供受限扫描，不循环诱导授权。

### 8.2 数据收集

默认收集：无远程遥测。

选择加入后可以发送：

- 引擎和规则版本；
- macOS 主版本和硬件架构；
- 匿名分类计数、耗时和错误码；
- 规则命中与误报反馈的匿名标识。

禁止发送：

- 用户名、完整路径和卷名；
- 文件名、文件内容和应用内数据；
- 稳定硬件标识；
- 未经单独确认的诊断日志。

## 9. 错误处理

错误被划分为以下领域类型：

- `permissionDenied`：解释缺失权限和受影响范围；
- `identityChanged`：目标已变化，跳过并要求重新扫描；
- `inUse`：目标活跃，保留并显示关联进程；
- `ruleConflict`：保护规则优先，停止该项；
- `volumeUnavailable`：卷已卸载或不可达；
- `helperUnavailable`：降级为无特权能力，不反复弹窗；
- `partialExecution`：展示成功、跳过和失败的逐项结果；
- `auditFailure`：无法可靠记录时禁止开始新的破坏性计划。

任何错误处理都不能通过扩大权限、放宽路径验证或改用永久删除来“提高成功率”。

## 10. 性能设计

- 使用 APFS 和目录元数据优先的分层扫描，避免读取文件内容；
- 对目录枚举设置并发和 I/O 预算，前台交互优先；
- 使用 SQLite 保存目录指纹、规则版本和最近扫描结果；
- 仅在目录身份或修改信息变化时增量重扫；
- 大目录持续流式返回进度，不等待全盘结束后才展示；
- 取消扫描必须及时停止新任务，并清理临时状态；
- 大小统计区分逻辑大小与实际占用，避免 APFS clone 误导用户。

性能目标：常用分类在启动后 2 秒内展示历史结果；增量快速扫描在典型开发者机器上 30 秒内给出首批可操作结果；完整磁盘分析允许持续运行但必须实时展示进度和可取消。

## 11. 安全设计

### 11.1 不可跨越的路径边界

引擎和 Helper 都必须拥有独立的拒绝列表，包括系统根、用户主目录根、卷根、应用支持根和其他高价值父目录。即使规则错误或变量为空，也不能删除裸父目录。

### 11.2 符号链接与竞态

- 扫描时记录字面路径和物理路径；
- 默认不跟随符号链接进入新树；
- 删除前使用文件描述符或等价的身份绑定方式重新确认父目录与目标；
- 路径解析结果发生变化时拒绝操作；
- 对扫描与执行之间的替换、挂载变化和硬链接情况建立专项测试。

### 11.3 规则供应链

- 规则包使用独立签名密钥；
- 更新通过 TLS 下载并验证签名和 hash；
- 支持紧急撤销有风险的规则；
- 保留上一份有效规则包以便回滚；
- 引擎设置最低和最高兼容 schema 版本；
- 更新失败时继续使用已验证版本，不加载部分文件。

### 11.4 纵深安全防线

一次清理操作必须连续通过多层独立防线，任意一层拒绝即停止该项：

1. **规则层**：规则签名有效、来源可追溯、适用当前 macOS；
2. **证据层**：归属、用途、可再生性、活跃性和共享性满足风险要求；
3. **计划层**：用户选择被固化到短期有效的不可变计划；
4. **授权层**：高权限请求绑定调用方签名、`planID` 和有限操作类型；
5. **路径层**：字面路径、物理路径、祖先目录和卷边界全部验证；
6. **身份层**：设备号、inode、文件类型、所有者和关键时间戳匹配；
7. **执行层**：优先采用原子移动，不把失败降级成更危险的操作；
8. **验证层**：执行后检查目标和恢复位置，确认实际结果；
9. **审计层**：记录结构化结果；无法可靠记录时禁止开始新计划；
10. **撤销层**：规则可远程撤销，隔离项可在保留期内恢复。

Helper 只接受计划产生的一次性能力令牌。令牌绑定调用方、计划、操作集合和失效时间，不能用于访问计划之外的路径，也不能在执行完成后重放。

### 11.5 安全熔断与事故控制

- 每个规则可以独立禁用，不必等待完整 App 发版；
- 规则服务支持按 macOS 版本、产品版本和硬件架构撤销；
- 同一规则连续出现异常跳过、恢复或失败反馈时自动停止推广；
- 单次执行中身份变化或保护冲突超过阈值时停止剩余同类操作；
- 产品始终保留本地基础保护规则，即使规则服务不可用也不能绕过；
- 客服或授权状态不能远程触发文件操作，只能提供诊断和规则状态；
- 事故响应优先关闭危险规则、保全本地审计记录并指导恢复。

### 11.6 不使用恐惧驱动的安全体验

安全不仅是文件系统约束，也包括避免诱导用户作出高风险选择。产品禁止：

- 使用虚构威胁、夸张健康分数或红色警报促进付费；
- 将“扫描到的总大小”冒充“可安全释放空间”；
- 默认勾选 `review` 或永久删除项目；
- 在购买按钮旁弱化删除风险或恢复限制；
- 以拒绝授权为由阻止用户访问已有历史和恢复功能；
- 在试用到期后阻止用户恢复试用期间隔离的数据。

### 11.7 Agent 场景专项安全

- 扫描器不解析或上传 Prompt、会话正文、代码内容和 MCP 响应正文；
- 配置分析只读取识别引用所需的结构，不展开环境变量或 Keychain 值；
- 日志预览默认遮盖用户名、仓库远端、Token 形态和完整路径；
- 活跃 Agent 进程、任务锁和最近持续写入共同构成运行保护；
- 跨 Agent 共用的包缓存和模型按引用计数处理，不能因单个 Agent 卸载而删除；
- Agent 生成物是否可重建不能仅由文件创建者判断，必须考虑用户是否已编辑、移动、提交或引用；
- Git 安全判断失败时保持 worktree，不尝试“修复”仓库以便清理；
- MCP 配置中的任意命令都视为不可信文本，扫描器绝不执行或 shell 展开。

## 12. 测试策略

### 12.1 单元测试

- 每种 matcher 和证据组合；
- 风险降级与保护规则优先级；
- 路径规范化、控制字符和遍历拒绝；
- 计划生命周期和过期行为；
- 规则签名、兼容性与回滚。

### 12.2 属性与模糊测试

建立不变量：任何可执行目标必须是绝对路径、不能是保护根、不能逃逸允许边界、必须有稳定身份和执行授权。针对路径解析、规则解码和 XPC 消息做 fuzz testing。

### 12.3 集成测试

- 临时 APFS 卷中的扫描、移动、恢复和跨卷失败；
- 权限允许、拒绝、撤销和 Helper 不可用；
- 扫描后替换文件、符号链接竞态和应用重新启动；
- 规则更新中断、签名错误和版本不兼容；
- 执行中崩溃后的历史恢复和幂等验证。

### 12.4 真实环境测试

覆盖仍在支持期内的 macOS 主版本、Apple Silicon 和 Intel。厂商专项规则在干净虚拟机或专用测试机上验证；每个 macOS 大版本发布后冻结高风险规则更新，完成兼容性回归后再恢复。

### 12.5 人机交互测试

- 使用可用性测试验证首次用户能否区分安全、审查和保护项目；
- 测试用户能否在不阅读帮助文档的情况下找到清理原因和恢复入口；
- 对权限请求、永久删除和卸载文案进行理解度测试；
- 使用 VoiceOver、仅键盘、Reduce Motion 和 Increase Contrast 完成全流程；
- 验证所有空间数字明确区分候选大小、计划大小和实际释放空间；
- 验证购买状态不会改变安全默认值、恢复权利和历史访问；
- 用错误注入测试身份变化、文件占用、Helper 中断和规则撤销时的用户反馈。

关键安全文案上线前要求至少 90% 的测试用户正确回答“将删除什么、是否可恢复、会造成什么影响”。

### 12.6 Agent 工程场景测试

- Codex、Claude Code、Cursor 及其他支持的 Agent 同时安装和并行运行；
- 同一 MCP Server 通过 `npx`、`uvx`、本地源码和容器重复安装；
- 用户自定义 Skill 与可重新下载 Skill 同名但内容不同；
- 活跃任务写入日志、截图或 patch 时扫描与执行发生竞态；
- worktree 包含未跟踪文件、未推送提交、stash、锁和进行中的 Git 操作；
- 多个 Agent 共用模型、包缓存、插件版本和项目索引；
- 配置包含环境变量引用、Keychain 引用和伪装成路径的恶意命令；
- Agent 目录从旧版本迁移、部分卸载或改变 schema；
- 离线状态下清理模型、运行时和包缓存的风险降级；
- 会话、Prompt、Skill 和 MCP 配置不会出现在遥测、诊断包或审计日志正文中。

## 13. 知识产权与来源治理

### 13.1 禁止来源

- Mole 或其他 GPL 清理工具的源码、脚本、测试和规则文件；
- 反编译商业清理产品获得的内部实现；
- 无法确认授权的数据集；
- 带有限制性条款且不允许商业再利用的社区列表。

### 13.2 允许来源

- Apple 官方文档与公开 API；
- 应用厂商公开文档和支持文章；
- 本团队在合法安装的软件上进行的文件系统观察；
- Bundle metadata、安装 receipt 和系统公开数据库；
- 用户主动提交并同意用于改进规则的匿名事实；
- 已确认兼容商业闭源使用的第三方组件。

### 13.3 来源台账

每条专项规则关联来源记录、验证步骤、验证人、日期、系统版本和测试证据。发布构建生成第三方许可证清单和规则来源报告，供内部法务与安全审计使用。

此设计降低知识产权风险，但不替代目标市场执业律师的正式法律意见。

## 14. 发布与更新

- 使用 Developer ID Application 签名 App、Helper 和所有嵌套可执行代码；
- 启用 Hardened Runtime；
- 构建 DMG 或 ZIP，提交 Apple notarization 并 staple ticket；
- App、Helper 和内置引擎作为一个签名版本原子更新；
- 规则包可以独立更新，但必须签名、可撤销、可回滚；
- CI 生成 SBOM、第三方许可证清单、测试报告和签名产物 hash；
- 正式版逐步放量，发现删除安全问题时立即停止规则发布并远程撤销相关规则。

## 15. 商业模式边界

技术架构支持订阅或买断，但 V1 不在引擎中引入按次计费。授权状态只控制商业功能入口，不能影响用户恢复数据、查看历史或卸载 Helper。

建议商业分层：

- 免费试用：完整扫描、风险解释和有限次数清理；
- 付费版：全部分类、应用卸载、开发者专项规则、持续规则更新；
- 团队版后置：集中策略、设备许可和组织规则包。

支付、账户系统和团队控制台属于独立商业子系统，不进入清理引擎 V1 的实现计划。

## 16. 分阶段交付

### 阶段 0：安全内核

交付路径模型、Candidate、CleanupPlan、规则 schema、身份验证、审计日志及测试夹具。只在临时目录和测试卷执行。

### 阶段 1：只读产品闭环

交付 SwiftUI 主框架、系统缓存扫描、应用缓存扫描、开发缓存扫描、安装包扫描、大文件分析、权限诊断和规则来源展示，并交付作为亮点模块的 Agent 资产地图以及 Skills、MCP、沙箱和 worktree 只读盘点；真实机器只扫描，不删除。

### 阶段 2：用户域安全清理

交付计划审查、废纸篓或隔离区移动、执行后验证、历史与恢复。操作范围限定在用户权限可访问区域。

### 阶段 3：应用卸载

交付应用归属发现、关联残留审查、共享数据保护、运行状态检查和用户域卸载。

### 阶段 4：特权 Helper

交付 XPC 协议、调用方验证、系统级缓存和受控 Helper/Daemon 移除。完成外部安全审计后才默认开放。

### 阶段 5：商业发布

交付授权系统、签名规则更新、自动更新、notarization、隐私政策、用户支持流程和渐进发布。

## 17. 成功指标

产品质量以安全和信任优先衡量：

- 已确认用户数据误删事故为 0；
- 所有执行目标拥有来源、证据和审计记录；
- 破坏性操作路径测试覆盖率 100%；
- 扫描崩溃不产生文件系统修改；
- 用户可理解的跳过或失败原因覆盖率达到 95%；
- 首次用户正确区分“可安全释放”和“建议审查”的比例达到 90%；
- 用户在 30 秒内找到单项清理依据和恢复方式的比例达到 90%；
- VoiceOver 和仅键盘能够完成扫描、审查、执行、历史与恢复全流程；
- 所有永久删除入口均与可恢复清理分离，且不存在默认选中路径；
- 规则熔断从确认问题到停止新命中的时间不超过 15 分钟；
- Agent 知识资产和凭据误分类为 `safe` 的测试结果为 0；
- 所有 worktree 候选项均能证明 Git 状态、恢复来源和非活跃状态；
- 用户能在 30 秒内理解清理 Agent 资产对旧会话和下次运行的影响；
- V1 试用用户完成首次扫描的比例达到 70%；
- 首次扫描后进入审查页的比例达到 50%；
- 付费用户 30 天内再次主动扫描的比例达到 40%。

商业转化指标不能驱动放宽安全策略；安全不变量高于清理空间和转化率。

## 18. 已确定的架构决策

1. 产品闭源商业化，清理引擎完全独立实现；
2. 不捆绑、不调用、不修改 Mole；
3. 使用 SwiftUI 和 Swift 6 原生技术栈；
4. 首发采用 Developer ID 官网分发；
5. 最低支持 macOS 13；
6. 产品保持面向普通用户、专业用户和开发者的完整清理能力，Agent 工程清理作为差异化亮点；
7. V1 不包含性能优化、杀毒和常驻硬件监控；
8. 默认可恢复删除，永久删除必须显式确认；
9. 规则必须具备独立来源和验证记录；
10. 特权能力最后交付，并在开放前接受外部安全审计。
11. Agent 资产按任务、项目、Agent、MCP 和 Skill 关系建模，不按隐藏目录整体清理；
12. 用户知识、凭据、配置和未提交工程状态拥有高于空间回收的保护优先级。

## 19. 评审结论标准

本设计通过评审需确认：

- 闭源商业化与独立实现路线符合产品目标；
- 首发用户和 V1 范围足够聚焦；
- `Scan → Plan → Review → Apply → Verify → Audit` 是唯一破坏性执行路径；
- 默认恢复策略和最小权限边界可接受；
- 规则来源治理满足后续法务审计需要；
- 分阶段交付顺序符合先安全内核、后真实删除、最后特权能力的原则。
