# SuperCleaner 0.3.20（94）交付记录

## 实际修改

1. 推荐清理栏目内的所有条目隐藏右侧风险标签，保留名称、大小和路径。栏目说明改为“已按清理规则筛选，可直接批量清理”。其他栏目的保护与手选提示保留。
2. 经过完整目录检查的 npm、pip、SwiftPM、Go build、Cargo 下载归档、CocoaPods 缓存按可再生缓存推荐清理，不再仅因存在 node、python、swift 等进程而留在保留组。凭证、外部链接、无法读取等具体问题仍会阻止推荐。
3. 已知缓存内指向自身目录内的框架链接不再导致整个条目永久保护；扫描不会沿链接继续遍历，指向缓存外的链接仍阻止删除。
4. Playwright 浏览器属于需要重新安装的运行文件，取消内部链接导致的误保护后允许手动选择，但不进入自动清理。Xcode 归档等工具运行数据同样要求手动选择。
5. uv 缓存继续交由 uv 管理，标签从笼统的“永久保护”改为“由 uv 管理”，并解释使用 `uv cache prune` 清理未使用内容。没有直接删除用户的 uv 缓存。
6. 残留归属匹配加入主应用 ID 后缀、关联扩展 ID、应用组 ID 和团队前缀，避免把已安装应用的偏好设置/扩展当成孤儿文件。扫描复用现有应用清单，执行验证使用相同归属规则。
7. 确认没有对应应用的文档/设置类残留显示“可手动清理”，并说明可能包含用户数据；仍允许逐项勾选，未自动加入批量清理。
8. 应用切回前台时的 Helper 状态读取改为后台执行；重复请求合并，只在状态变化时发布界面更新。注册操作开始时取消旧刷新，防止旧状态覆盖新操作结果。
9. 切回前台不再额外触发隔离区维护，保留原有定时维护；删除期间不启动维护。推荐分类结果随候选列表缓存，避免无关状态刷新时重新分组。

## 分类依据

- [uv 官方缓存文档](https://docs.astral.sh/uv/concepts/cache/)要求由 uv 管理缓存，缓存操作使用共享锁；直接修改缓存不是受支持的清理方式。
- [Playwright 官方浏览器文档](https://playwright.dev/docs/browsers)说明浏览器需要安装及下载。可重新下载不代表删除后相关任务无需额外操作即可继续运行。
- “未找到已安装应用”是归属线索，不证明容器里的文档、设置或共享数据没有价值。因此文档类残留允许手动清理，而不默认选中。
