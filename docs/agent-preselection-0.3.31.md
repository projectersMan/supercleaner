# Agent 预选规则 0.3.31（105）

本批次将 Agent 页头缩短为一行，并修正默认勾选的边界。Similarity 表示能力描述的覆盖证据，不表示不同平台能共用同一个配置。

## 默认保留和清理顺序

1. 用户明确保留的项目、全局及共享资源不自动勾选；用户仍可手动选择可删除项目。
2. 仅同 Platform、同类型的对象计算覆盖关系。Codex Skill 与 Claude Skill、不同平台的 MCP，以及 Skill 与 MCP 之间均不比较。
3. 优先评估缓存副本，再评估非全局的其他副本。缓存不能仅凭目录名自动选择；必须有本轮未选中的同平台对象提供达到当前阈值的覆盖。
4. 已选删除的对象（含手动选择）不能作为其他删除建议的保留依据。每个建议的覆盖来源会锁定保留，避免整组相互覆盖的副本全部被勾选。
5. 不根据名字或文件数量认定“更有用”。唯一对象、覆盖不足或缺少有效分析索引时不自动选择。相同优先级仍沿用联合覆盖及稳定排序，保持结果可重复。

例如：同平台全局 A 与缓存 B 重复时保留 A、预选 B；项目 A 与缓存 B 重复时优先选择 B；只有两个重复缓存时至少保留一个；Codex A 与 Claude B 即便描述完全相同也都不能以对方为删除依据。

## 已确认的问题及修改

- 旧规则先无条件将可选的 `.cache` 对象加入计划。新增回归用例在修改前出现 3 项测试、6 个断言失败，覆盖唯一缓存被选中、缓存整组被选中、手动删除项被用作隐含保留来源。
- 分析输入和索引记录现在带 Platform。计算、推荐的覆盖并集及支持集核对均检查同平台和同类型，不能仅在界面上按平台过滤。
- 旧索引的 Platform 由本轮发现的真实目录记录补齐，清除跨平台关系和旧推荐缓存；未确认平台的条目不能提供覆盖。保留可复用的向量，避免仅为增加平台边界重新运行嵌入模型。平台变化会撤销旧分组的完整性证明。
- 底部数量改称“清理单元”，与顶部 Skill/MCP 对象数量区分；修复“全部平台”视图引用旧的空分组，从而把屏幕上已有的选择误报为全部被筛选隐藏的问题。现在根据当前 Skills/MCP 标签及平台筛选统计可见单元。
