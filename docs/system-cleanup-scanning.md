# System Clean Up：扫描补齐与选择边界

验证日期：2026-10-29。范围仅为系统清理；不复用卸载候选来删除应用用户数据。

## 已落实的行为

1. **部分结果保留**：每个发现根、每个候选目录分别计入扫描预算。一个目录达到条目/深度上限或不可读，不会清空前后已完成候选；未完整检查的目录不可删除，报告保留具体路径和原因。刷新报告也保留这些限制。
2. **Chrome**：按 Default、Guest Profile、数字 Profile N 发现普通缓存，以及独立的 Service Worker CacheStorage/ScriptCache。不会把配置目录、Cookie、密码库、历史、IndexedDB 或 Local Storage 整体作为清理根。
3. **应用缓存/日志**：根据已安装应用元数据，将标准用户 Caches/Logs、精确沙盒 Caches/Logs、声明的共享组缓存与部分 Application Support 派生缓存叶子归入应用。支持厂商目录下一层适配；没有唯一归属的内容保留通用发现。日志只匹配明确日志扩展名；不删除 Application Support、Documents 或整个容器。
4. **微信**：4.x 的多账号 cache 及 app_data/log 下 xlog；旧版沙盒缓存仍按精确容器路径发现。没有将聊天 msg/Message、数据库、附件、备份、下载目录加入专项扫描。缓存内出现敏感名称、链接或无法完整验证的内容，整个候选仍被阻止。
5. **默认选择边界**：一键清理只处理完整验证、风险为 safe、规则明确允许默认选择、未标记活动且不要求手动确认的项目。精确归属的普通应用缓存不设年龄门槛，但任何不完整扫描、敏感内容或链接都会取消默认资格。深度清理页可展示并允许用户逐项处理 review 项；其它应用的离线内容和共享缓存仍要求手动选择。用户此前明确指定的一组 Chrome CacheStorage/ScriptCache 可进入一键清理，扫描时保留相应提示。
6. **运行中缓存**：归属明确的普通应用缓存及上述 Chrome 离线缓存可在应用运行时进入隔离清理；执行前会重新发现目标并验证身份。共享缓存、其它应用的离线内容和日志不适用此例外。缓存可能立即重建；Chrome 离线页面可能暂时不可用。
7. **展示与接口**：系统清理按应用、缓存/日志类型分组；未归属项有独立分组；显示未完整扫描的位置和逐项选择提示。GUI 一键清理与只读 CLI 预览共用同一条默认候选筛选策略。
8. **执行复核**：执行时重新读取应用元数据，重新发现精确目标并检查内容、活动状态和保护清单；失效的规则/目标拒绝执行。仍通过原有计划、身份校验和隔离流程处理。

## 范围与预算

- 应用清单：最多 30,000 条目、12 层；关联目录发现每层最多 10,000 项。
- 应用专项目标：每个目标最多 100,000 条目、16 层；静态规则沿用各自预算。
- 静态精确规则优先；通用扫描拆开包含专项根的祖先，保留其它兄弟项；历史残留不得覆盖专项目标。
- 受限不等于干净。扫描总大小也不等于可安全释放大小，更不代表已经释放。
- 本实现不提高用户权限，不自动获取完全磁盘访问，不修改用户文件内容，不搬迁聊天数据。

## 独立来源

入口与结构由本项目重新实现；未导入腾讯 Lemon 的源码、XML、规则表或资源。腾讯截图仅用于比较覆盖与交互差异。

- Chromium 官方 user_data_dir 文档：用户数据与缓存路径的关系、profile 目录惯例。
- Electron `app.getPath`：userData/sessionData/logs/cache 的平台语义。并非所有应用都使用同一 Electron 布局，因此只列明确缓存叶子。
- Chrome Workbox Cache Storage 文档：缓存可能支撑离线体验，不能等同于自动可删除内容。
- 本机 macOS 26.5.2 (25F84) 的只读目录元数据观察：Chrome、ChatGPT（Bundle ID 为 com.openai.codex）、微信 4.1.15、Trae CN、Lark 等。没有读取聊天正文、浏览器数据库或凭证内容。
- 来源编号：`SRC-SYSTEM-APP-CLEANUP-001`，详见 rule-sources.md。

## 验证

`SystemCleanupContract` 使用独立临时目录验证：预算耗尽和不可读兄弟目录、发现预算、Chrome 多 profile、微信多账号、Electron 叶子、真实 Bundle ID 归属、目录去重、静态规则优先、离线选择全链路、旧 JSON 兼容、新增保护/凭证/符号链接、应用运行检查，以及实际隔离后用户文件哨兵仍然存在。

新增契约纳入默认 CoreContractChecks，也可单独运行：

```sh
swift build --product CoreContractChecks
.build/debug/CoreContractChecks --check-system-cleanup
```

本机只读采样（目录会随应用运行变化）：共 1,629 个候选、约 20.88 GB；Chrome 约 6.35 GB，其中离线内容约 4.96 GB；微信约 0.68 GB；ChatGPT 约 1.75 GB。均为发现量，包含活动或受保护内容，不能作为清理收益承诺。没有发现候选之间的父子重叠。

特别观察：ChatGPT 较大的缓存是 Sparkle 更新器展开的应用包，包含链接且超过检查深度；微信部分 cache 后代名为 Message。两者继续保持不可删除，未为了对齐 Lemon 数字降低保护标准。真实目录只做读取；实际移动/隔离测试仅作用于测试夹具。
