# SuperCleaner 0.3.30（104）

## 本批次修改

- 清理中心的“清空废纸篓，即可立即释放磁盘空间”提示加粗。
- Agent 筛选工具栏紧接页头分隔线，使用与卸载、大文件页面一致的全宽背景、左右边距和 44 点内容高度（另含底部分隔线），移除原来的圆角卡片外边距。
- 清理普通垃圾或大文件时保留未变化的 Agent 展示关联，避免随后切页退回同步重建列表。
- 删除进度区分逐项处理、移入废纸篓和保存清理/恢复记录；移入废纸篓也持续报告数量及当前文件。
- 清理中心取消逐项失败、需要重新扫描和重试提示；结果页仅列出成功项，无成功结果时静默结束，内部历史和执行日志保留原有真实结果。
- 元数据、数据声明及历史记录仅复用已检查的输入；新扩展、应用代码或元数据变化会使对应复用失效。应用清单、运行状态和执行策略继续实时检查。
- 嵌套扩展的独立 Bundle ID 纳入归属识别。容器归属声明不完整时不默认推荐，执行前继续核对；不根据 `extension` 这一名称作删除判断。
- 输入法应用库存补齐 `/Library/Input Methods`、用户级及系统级对应目录。输入法程序及其运行缓存不进入常规清理或卸载，旧缓存候选执行前也会被拒绝；其他应用缓存仍正常扫描。
- 权限生效后，自动恢复扫描时将 SuperCleaner 主窗口带到前台并关闭自身的准备弹窗。macOS 系统设置是独立应用，本次不强制终止它。

## 诊断边界

- 实机采样确认历史残留执行前会反复枚举已安装应用并读取签名元数据；本次减少未变化元数据的重复读取，不取消目录归属检查。
- 同一只读探针连续两次核对本机 115 个应用：首次 13.822 秒，复用未变化元数据后 0.181 秒，均无不可访问根目录。此数值仅代表库存阶段，不代表完整卸载耗时。复用按当前代码输入失效，不按经过时间丢弃未变化的结果。
- 5 万候选的清理路径归并约 0.1 秒，未复现长时间收尾，未据此宣称它是瓶颈。
- 收尾采样未覆盖用户截图停留的完整时段，不能给出真实卸载、废纸篓系统调用的加速倍数。新增阶段进度用于区分真实工作；系统移动耗时仍由文件及系统状态决定。
- 新 GUI 进程启动的采样停在 macOS `InitializeInputSourceCache / SetCCFFileLock`。本机存在安装在 `/Library/Input Methods` 的豆包及搜狗输入法，而此前普通应用目录库存未覆盖它们；历史记录显示对应缓存曾参与清理。这是确认的归属缺口，但不足以单独证明系统锁的全部成因。

## 与远程代码的差异

拉取远程后，`main` 和 `origin/main` 同在 `f5d6ed7`，远程版本为 0.3.8（82）。本地改动包含随后多个批次，涉及权限、垃圾分类、卸载与安装记录、Dock、大小统计、Agent 增量分析及性能、源码职责拆分、大文件识别与交互、回归测试和诊断文档。提交信息按全部实际差异整理，不只描述本次字体修改。

构建目录中的应用、DMG、真实模型副本和遗留临时测试目录不作为代码提交内容。模型源码继续保留 Git LFS 指针。
