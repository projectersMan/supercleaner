# 架构与当前行为

SuperCleaner 使用 Swift 6、SwiftUI 与 AppKit，支持 macOS 13 起的系统。产品边界是只读发现、明确选择、不可变计划、执行前实时复验、可恢复隔离和持久化历史。目标与依赖见 [Package.swift](../Package.swift)。

## 模块

| 模块 | 职责 |
| --- | --- |
| CleanerCore | 发现、归属、安全策略、计划、执行、规则、历史、恢复与调度 |
| CleanerApp | 导航、选择、展示、权限恢复、批次协调 |
| CleanerHelper | 经过授权的受限应用文件操作 |
| AgentOverlapAI / AgentInference | 本地 Agent 能力分析与独立推理运行时 |
| CoreContractChecks | 独立开发契约验证；不是用户 CLI |

`AppInfrastructure` 构造共享运行时与协调器；界面不另建执行器。独立用户 CLI 已退役。

## 六维度扫描

`SystemScanCoordinator` 将系统、应用、大文件、Agent、本地模型和项目结果按同一个 generation 合并到 `SystemScanReport`。模块独立发布、取消和继续；继续重跑该模块。waiting/scanning 优先显示统一进度，其他已完成模块仍可浏览。全扫描用时由 AppModel 记录，包含准备和 Agent 分析；单模块刷新不改写上次完整扫描时间。

- 系统清理先区分建议清理与深度清理，再并列展示 System 与具体应用。普通应用缓存和日志可推荐；共享缓存、离线内容及微信聊天内容需手选。
- 应用卸载按 Protected、Running、Uninstallable 分类，All 为汇总。运行、系统保护、共享内容及真实归属限制继续生效。退出后复用预备计划，重启后清除无效卸载选择。空选择不强制生成全量卸载计划。卸载只按应用勾选，展开行只展示关联文件及收据；应用一级勾选纳入全部可卸载关联项（包括归属明确的用户数据），收据继续通过专用处理流程执行。
- 大文件先发现，再验证精确副本及 ZIP/同级目录。保留件证明必须进入计划和移动前复验。自适应目录分组、三态勾选与搜索只控制可见列表；首页汇总包括其他筛选下仍被选中的文件。
- Agent 按供应商、平台、Skill/MCP 展示。MCP 只提取名称、传输方式与归属，不保存密钥、环境变量或请求头。能力分析只为有已验证保留覆盖、当前可删除的资源提出预选；手动保留决定不因后台分析或导航被覆盖。
- 本地模型覆盖 Hugging Face、LM Studio、Ollama、PyTorch、Whisper、Keras、GPT4All。模型初始不选中；手动选择可加入首页总计划。候选与祖先链接不接收；内部链接不跟随。布局、身份和元数据指纹在执行前再次检查。
- 项目由 manifest 识别，发现 `node_modules`、`target`、`.build`、`build`、`dist` 和项目安装包，不能凭同名目录直接认定。Git 跟踪状态不是唯一安全依据；凭据、非托管嵌套仓库、不可读内容和不完整检查仍保持保护。

项目和模型不以进程运行状态判定可清理性，其他保护仍生效。依赖目录中的链接随目录移动，不遍历其目标。

## 选择与首页计划

项目预选由设置 `projects.preselectArtifacts` 控制。没有保存值时默认开启；明确保存的关闭值继续生效。预选只在对应模块发布新报告时应用，不能在 View.onAppear 或无关模块更新时重新全选。手动取消、筛选和其他模块选择保持独立。设置切换即时更新当前选择与首页缓存，关闭只撤销自动选择。

项目扫描根由 `ProjectScanRootsStore` 持久化。设置保存已有报告时只刷新项目模块，未扫描时只保存配置；旧扫描范围与当前配置不一致时不得执行旧项目结果。

`defaultCleanupSelection` 只用于推荐资格和推荐/手动/混合分类。首页行显示“推荐选中 / Recommended Selected”、“手动已选 / Manually Selected”或“当前已选”。未扫描的维度不预先显示手动提示。

`cleanupCenterSelection` 汇总六维度全部当前可执行的已选项，包含手动模型、应用卸载和手选项目。底栏合计和清理按钮共同使用这一个集合，保留原有底栏用词。搜索、目录折叠或大文件子范围不缩小首页计划。尚未就绪、正在重扫、配置过期、受保护、已处理或待单独重试的项目不混入当前计划。

`CleanupSelection` 在全局按路径、父目录及 Ollama 共享依赖合并实际文件操作，容量不重复相加。`PlanBuilder` 必须先复验每个原始选择，再去重；不能先丢弃别名或被父目录覆盖的候选，以免绕过保留件与保护冲突。

项目分组标题和产物行均提供 Finder 与永久保护菜单。标题保护项目根目录；保护保存后立即撤销全部受影响子项的选择，包括被筛选隐藏的项。保护列表变更使展示及计划缓存失效，执行前仍重新读取。

## 执行与恢复

`CleanupExecutionCoordinator` 顺序持久化执行日志、执行文件操作、保存回执、登记保留调度，最后才删除日志。相同 planID 不得重放。源与目标身份、路径、当前规则及激活标识、保护清单、保留件、可用权限和计划时效都在实际移动边界复验；Helper 回退用户态也不能跳过终验。

应用关联校验不共享整批固定 15 秒额度，也没有外层固定 60 秒截断；用户仍可停止，迟到验证不能移动文件。BOM 仅缓存成功解析文本并按文件 generation 校验，不缓存最终归属。先保存恢复记录，再更新 Dock；各阶段分别报告状态。

恢复不覆盖已有路径，冲突时使用稳定的新位置。恢复、彻底删除和维护按回执互斥，并用 resolution journal 收敛中断结果。未知结果保留日志，不伪造成功。新保护及规则撤销对旧计划仍有效。

Ollama 按清单/tag 选择。所有引用模型均被选中时共享 blob 才加入计划；实际清单移除成功且移动前无剩余引用时才移动。APFS 写时复制快照只位于验证过的计划/候选隔离路径；后批清理不破坏前批恢复。普通清理仍不得移走整个 SuperCleaner 数据目录。

## 清理计量、废纸篓与磁盘

`CleanupSessionSummary` 按成功回执及候选归属去重累计，六维度和等于全局总计，重扫不清零；失败与跳过不增加。清理逻辑字节不等于立即释放的物理空间。

`DiskCapacityMonitor` 独立管理 Home 所在卷的总量、已用和当前用户可用量。启动、每分钟、激活及操作后后台读取，同一时刻只读一次，相同值不发布。失败显示错误，不用零值掩盖；容量更新不驱动整张清理列表重算。

首页、关闭和退出共用 `TrashReminderController` 的确认与执行入口。未经确认不调用 Finder；取消、失败或未确认已空时不确认累计量。只读扫描期间允许手动清空，扫描继续；真实清理、更新及重复清空仍互斥。退出等待已批准操作，Cancel 可直接退出而不清空。永久提醒偏好独立于操作成功，新增清理可再次提醒。

## 更新与发布边界

规则签名、激活与撤销由共享运行时复验。Sparkle 2.10.0 的签名 appcast/DMG 处理应用升级。未提供正式公开配置时，不嵌入示例配置启用更新。

本地临时签名不代表 Developer ID、公证或干净机验收完成。Helper 的真实启用和发布阳性条件见 [激活审计](helper-activation-audit.md) 与 [生产发布清单](production-release-checklist.md)。已完成计划、旧布局和历史机器记录统一见 [归档](history.md)。

正式 App 的 Core 策略和 Agent 模型从 `Contents/Resources` 的包内资源加载；开发或 XCTest 才回退 SwiftPM 资源。独立运行验证暂时隐藏编译目录，防止绝对构建路径的资源回退掩盖打包缺失。
