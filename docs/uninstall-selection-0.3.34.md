# 0.3.34 应用卸载父子勾选同步

## 原因和修改

- 普通卸载文件与安装收据分别保存选择状态。原来的总框只切换普通文件，也只用普通文件判断全选，因此 OneNote 的 plist、bom 两个收据子项没有跟随选中。
- 总框现在统一控制该应用的所有可选子项，并用文件与收据的共同状态判断未选、半选、全选。半选时再次点击总框会补齐全部子项；取消全选会清除两类选择。
- 清空选择同时重置收据选项。其他应用使用同一逻辑；已有其他应用的选择不受单个应用总框影响。
- 收据行的来源筛选由界面与模型共用。一个安装包的 plist、bom 仍是同一个系统收据选项；收据不会成为普通文件删除项。原有的完整卸载确认及收据清理校验保持不变。

## 验证

- 修复前运行真实 AppModel 的 `--scan-cleanup-self-check`，稳定复现 `parent selection must include ordinary files and both receipt rows` 失败；修复后通过。
- 新增五项单元测试，覆盖文件与收据全选/取消、半选补齐、多应用选择隔离、无收据应用，以及有效收据来源筛选。
- Debug、Release 各 226 项测试通过。打包应用的模型自检覆盖总框、普通子项、收据子项、清空选择及执行中禁止修改选择。
- Computer Use 使用实际 ApplicationsView 和 AppModel 的隔离 OneNote 数据验证：五个普通文件加两个收据行，共七个子项全部跟随总框勾选；取消普通子项或收据后显示半选；点击半选总框恢复全选；取消总框与清空选择均清除所有子项。未对真实应用或用户文件执行卸载。
- CoreContractChecks、打包后 `verify-app.sh` 以及 DMG CRC 校验全部通过。
